WORKOUTS FRONTEND – DOCKERIZÁLÁS
===================================

Ez a jegyzet kizárólag a Workouts Angular frontend Dockerizálását foglalja össze.

1. A FRONTEND PROJEKT
---------------------
Technológiák:
- Angular 19
- Node.js 22 a Docker build során
- Nginx Alpine a futtatáshoz

A projekt főbb fájljai:
- angular.json
- package.json
- package-lock.json
- Dockerfile
- nginx.conf
- src/
- public/

2. MI TÖRTÉNIK DOCKERIZÁLÁSKOR?
--------------------------------
A frontendnél kétlépcsős Docker buildet használunk.

1. lépcső – Angular build:
- Node 22 Alpine image indul.
- A package.json és package-lock.json bekerül.
- npm ci telepíti a függőségeket.
- A teljes frontend forrás bekerül.
- npm run build elkészíti a production Angular buildet.

2. lépcső – Nginx:
- nginx:alpine image indul.
- Az Angular build eredménye bekerül az Nginx webrootjába.
- Az nginx.conf beállítja, hogyan szolgálja ki az Angular alkalmazást.
- A végleges containerben már nincs szükség Node.js-re.

3. A DOCKERFILE
----------------
A jelenlegi Dockerfile:

FROM node:22-alpine AS build

WORKDIR /app

COPY package*.json ./

RUN npm ci

COPY . .

RUN npm run build


FROM nginx:alpine

COPY --from=build /app/dist/ /usr/share/nginx/html/

COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]

Fontos:
A build stage-ben történik az Angular fordítása.
A végleges image már csak Nginx-et tartalmaz.

4. ANGULAR BUILD
----------------
Lokálisan a build parancs:

npm run build

A sikeres build eredménye például:

dist/workouts-frontend/

A Docker build ezt automatikusan elvégzi, tehát nem szükséges a dist könyvtárat Gitbe feltölteni.

5. DOCKER IMAGE ELKÉSZÍTÉSE
----------------------------
A frontend projekt könyvtárában:

docker build -t workouts-frontend:1.0.0 .

Az image ellenőrzése:

docker images | grep workouts-frontend

6. FRONTEND CONTAINER INDÍTÁSA
-------------------------------
Példa:

docker run -d   --name workouts-frontend   -p 8086:80   workouts-frontend:1.0.0

A port mapping jelentése:

HOST 8086  ->  CONTAINER 80

Tehát a böngészőből:

http://192.168.1.37:8086

A containerben az Nginx a 80-as porton figyel.

7. CONTAINER ELLENŐRZÉSE
-------------------------
Futó container:

docker ps

Minden container:

docker ps -a

Frontend log:

docker logs workouts-frontend

Nginx konfiguráció ellenőrzése:

docker exec workouts-frontend nginx -T

Containerben lévő fájlok:

docker exec workouts-frontend ls -la /usr/share/nginx/html

8. AZ ANGULAR API URL
---------------------
A production környezethez tartozó fájl:

src/environments/environment.prod.ts

A jelenlegi beállítás:

export const environment = {
  production: true,
  apiUrl: 'http://localhost:8080/api'
};

Dockeres környezetben ezt később módosítani kell.

Fontos:
A böngésző számára a localhost a FELHASZNÁLÓ GÉPE.
Nem a backend Docker containerét jelenti.

Ezért a végleges frontend API URL-t úgy kell kialakítani,
hogy a böngésző ténylegesen elérje a backend API-t.

9. FRONTEND ÉS BACKEND KAPCSOLATA
----------------------------------
A célarchitektúra:

Böngésző
   |
   v
Frontend Nginx
   |
   v
Backend API
   |
   v
PostgreSQL

A frontend JavaScript kódja a böngészőben fut.
Ezért az API URL-nek a böngésző számára elérhető címet kell használnia.

10. NGINX ÉS ANGULAR ROUTING
-----------------------------
Angular SPA esetén fontos, hogy az Nginx a nem létező statikus fájlokat
az index.html-re irányítsa.

Tipikus beállítás:

location / {
    try_files $uri $uri/ /index.html;
}

Ennek köszönhetően például egy Angular route:

/dashboard
/users
/workouts

közvetlen böngészőből történő megnyitása is működik.

11. GIT – DOCKERFILE
--------------------
A Dockerfile-nak Gitben verziózva kell lennie.

Ellenőrzés:

git ls-files | grep Dockerfile

Branch ellenőrzése:

git branch

Ha a Dockerfile egy adott branchben van, akkor a Dockeres szerveren
ugyanazt a branch-et kell checkoutolni.

Példa:

git fetch origin
git checkout MemberSearchServiceRefactor

Ellenőrzés:

ls -la Dockerfile .dockerignore

12. .dockerignore
-----------------
A .dockerignore célja, hogy felesleges fájlok ne kerüljenek a Docker build contextbe.

Például tipikusan:

node_modules
dist
.angular
.git

Ez gyorsítja a buildet és csökkenti a build context méretét.

13. HA A PORT FOGLALT
---------------------
Ha például a 8086 már használatban van:

docker run -d   --name workouts-frontend   -p 8087:80   workouts-frontend:1.0.0

Ekkor:

HOST 8087 -> CONTAINER 80

Port ellenőrzése:

ss -ltnp | grep ':8086'

Docker portok:

docker ps --format 'table {{.Names}}	{{.Ports}}'

14. FRONTEND FRISSÍTÉSE
-----------------------
Ha módosul az Angular kód:

1. Git commit/push
2. Docker szerveren git pull
3. új image build
4. régi container leállítása/törlése
5. új container indítása

Példa:

git pull

docker build -t workouts-frontend:1.0.0 .

docker stop workouts-frontend
docker rm workouts-frontend

docker run -d   --name workouts-frontend   -p 8086:80   workouts-frontend:1.0.0

16. KÖVETKEZŐ LÉPÉSEK
---------------------
A frontend image elkészítése után:

1. docker images ellenőrzése
2. frontend container indítása
3. böngészőből ellenőrzés

MEGJEGYZÉS
----------
A mostani frontend Dockerizálás célja elsősorban az Angular alkalmazás
production buildjének Nginx-en keresztüli kiszolgálása.

A backend, PostgreSQL, reverse proxy és CORS külön kérdés;
ezeket ebben a jegyzetben csak annyira érintjük, amennyire a frontend
működéséhez szükséges.
