# GUI E2E test set — 2026-09-28

The GUI suite contains 10 distinct browser-level Playwright tests, organized under the existing AUTH / COACH / USER / INTEGRITY structure.

1. AUTH/GUI — login empty-form validation with concrete Angular invalid-state and visible validation feedback
2. AUTH/GUI — login language selector
3. COACH/GUI — all five coach dashboard action surfaces
4. COACH/GUI — coach profile concrete editable fields + save action
5. COACH/GUI — program builder required fields + calculated end date
6. USER/GUI — all three dashboard navigation targets
7. USER/GUI — concrete editable profile fields + save action
8. USER/GUI — workout calendar previous/next month navigation
9. USER/GUI — assigned program card → workout occurrence → userWorkoutId → exercise route
10. INTEGRITY/GUI — USER attempting /coach/dashboard is redirected to /user/dashboard and the user dashboard is rendered

The suite does not use a business-data `test.skip()` for the My Programs flow: an incorrectly empty fixture now fails the test instead of silently reducing coverage.
Authentication setup requests are excluded from the read-only mutation guard because login/refresh are test setup traffic; business-data mutations are still rejected.
Older timestamped duplicate GUI files were removed so each GUI scenario exists exactly once.
